# Purview Detailed Design

## 1. Design Intent

The implementation provisions a production-oriented Purview landing zone with private connectivity, security controls, diagnostics, and optional cost governance.

- Providers and cross-subscription DNS provider alias: `providers.tf`

  - `env/prd/data-governance/terragrunt.hcl`

## 3. Resource Design

### 3.1 Resource Group and Naming

- Resource group name comes from the naming module output.
- The following names are generated by naming conventions:
  - Resource Group
  - NSG
  - Key Vault
  - Diagnostic Storage
- Purview account name remains explicit input.

### 3.2 Purview Account

- Deploys Microsoft Purview account with system-assigned managed identity.
- Uses a dedicated managed resource group for Purview-managed services.

### 3.3 Network Security Group

- Explicit outbound allow-list for required service tags:
  - AzureActiveDirectory
  - AzureMonitor
  - Storage
  - EventHub
  - AzureKeyVault
  - VirtualNetwork
- Default deny rules are applied for unmatched inbound/outbound traffic.

### 3.4 Private Endpoints and DNS

- Private endpoints are created for:
  - Purview account
  - Purview portal
  - Key Vault
  - Diagnostic Storage blob
  - Diagnostic Storage queue
  - Diagnostic Storage dfs
- DNS zone strategy is switchable:
  - Create zones in this deployment when `create_private_dns_zones = true`
  - Reuse existing hub zones when `create_private_dns_zones = false`
- Existing DNS zones can be read from another subscription through `azurerm.hub` provider alias.

### 3.5 Key Vault

- RBAC authorization enabled.
- Public network access disabled.
- Soft delete and purge protection enabled.
- Network ACL default action set to deny.

### 3.6 Diagnostic Storage

- StorageV2 with GRS and private access controls.
- Public access disabled.
- Shared key access disabled.
- Network rules default to deny.

### 3.7 Diagnostics and Monitoring

- Purview diagnostic settings send telemetry to:
  - Log Analytics workspace
  - Diagnostic storage account
- Metrics include `AllMetrics`.

### 3.8 RBAC Model

Purview managed identity receives:

- Subscription `Reader`
- Key Vault `Key Vault Secrets User`
- Diagnostic storage `Storage Blob Data Contributor`
- ADLS `Storage Blob Data Reader`
- Databricks workspace `Reader`

### 3.9 Budget and Cost Controls

- Budget module is optional through `enable_purview_budget`.
- When enabled, monthly budget is created on the Purview resource group with:
  - 80 percent actual threshold
  - 90 percent forecast threshold
  - 100 percent actual threshold

### 3.10 Managed Private Endpoints

- Optional module to request Purview managed private endpoints to:
  - ADLS
  - Databricks
- Controlled by:
  - `create_managed_private_endpoints`
  - `enable_adls_managed_endpoint`
  - `enable_databricks_managed_endpoint`

## 4. Configuration Inputs

Key mandatory inputs:

- `subscription_id`

- `location`

- `naming_suffixes`

- `existing_vnet_resource_id`

- `adls_storage_account_resource_id`

Feature flags:

- `create_private_dns_zones`
- `create_managed_private_endpoints`
- `enable_adls_managed_endpoint`
- `enable_databricks_managed_endpoint`
- `enable_purview_budget`

## 5. Deployment Flow

1. Resolve environment and naming inputs.
2. Resolve VNet and optional existing DNS zones.
3. Create resource group.
4. Deploy Purview, NSG, Key Vault, and diagnostic storage.
5. Create private DNS zones or bind existing hub zones.
6. Create private endpoints and DNS associations.
7. Configure diagnostics.
8. Apply RBAC assignments.
9. Optionally create budget.
10. Optionally request managed private endpoints.

## 6. Operational Considerations

- Ensure subnet policy and private endpoint subnet readiness in the landing zone.
- If using existing DNS zones in hub subscription, ensure the deployment identity has read access in the hub subscription and resource group.
- Managed private endpoint requests require downstream approval at data source owners.
- Remote module source access requires valid Git SSH host trust and credentials.

## 7. Outputs and Integration

Primary outputs expose:

- Resource group name
- Purview resource name and ID
- Purview managed identity principal ID
- Purview catalog and scan endpoints
- Key Vault resource ID and URI
- Diagnostic storage resource ID
- Private endpoint IDs
- Purview managed resource group ID
- Managed private endpoints created
